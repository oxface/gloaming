# Workflow deployment continuity

This standalone consumer runs two separately compiled executable builds against the same
PostgreSQL database. Earlier creates an export, retains its original input/state and admits a
delayed renderer reply. Current keeps definition version 1 and its named continuations, adds an
optional state annotation, and continues that retained work. There is no Wholesale dependency.

The builds share finite host/database wiring. `EARLIER_BUILD` selects the original state shape
and continuation implementation; Current adds `ReviewedByBuild`. The checked-in
[fixtures](fixtures) are literal v1 JSON, never generated by the current DTO serializer. Preserve
them when changing Current. Neither build automatically upgrades stored JSON or definition versions.

From the repository root, with the SDK selected by [global.json](../../../../../global.json)
and reachable PostgreSQL:

```bash
export WORKFLOW_DEPLOYMENT_CONNECTION='<disposable PostgreSQL connection string>'
dotnet build src/Gloaming.Messaging/tests/WorkflowDeploymentTests/WorkflowDeploymentTests.csproj -m:1
dotnet src/Gloaming.Messaging/tests/Fixtures/WorkflowDeployment/Earlier/bin/Debug/net10.0/WorkflowDeploymentDemo.Earlier.dll setup
dotnet src/Gloaming.Messaging/tests/Fixtures/WorkflowDeployment/Earlier/bin/Debug/net10.0/WorkflowDeploymentDemo.Earlier.dll start 84179010-ce2a-4085-87f5-806c71b14a65 src/Gloaming.Messaging/tests/Fixtures/WorkflowDeployment/fixtures/input-v1.json
dotnet src/Gloaming.Messaging/tests/Fixtures/WorkflowDeployment/Earlier/bin/Debug/net10.0/WorkflowDeploymentDemo.Earlier.dll receive 84179010-ce2a-4085-87f5-806c71b14a65 src/Gloaming.Messaging/tests/Fixtures/WorkflowDeployment/fixtures/reply-v1.json e1140b42-2842-4775-b177-45ca37263e3d
dotnet src/Gloaming.Messaging/tests/Fixtures/WorkflowDeployment/Current/bin/Debug/net10.0/WorkflowDeploymentDemo.Current.dll process
dotnet src/Gloaming.Messaging/tests/Fixtures/WorkflowDeployment/Current/bin/Debug/net10.0/WorkflowDeploymentDemo.Current.dll read 84179010-ce2a-4085-87f5-806c71b14a65
dotnet src/Gloaming.Messaging/tests/Fixtures/WorkflowDeployment/Current/bin/Debug/net10.0/WorkflowDeploymentDemo.Current.dll signal 84179010-ce2a-4085-87f5-806c71b14a65
```

Each invocation is a separate process that exits after one operation. `setup` is finite, explicit
disposable proof setup using `EnsureCreated`; runtime commands never reset or provision storage.
This is not a production migration tool. `receive` is a finite trusted proof intake which binds
the supplied literal payload/delivery identity to the stored pending command. An actual transport
must admit producer/tenant and preserve incoming correlation/causation rather than reconstructing
them from the process row. The sample does not dispatch `export.prepare` or run a real renderer;
no external rendering side effect or broker deployment guarantee is claimed.

`drain` reports local active workflow and pending reply counts; exit 12 means local work remains.
It includes `AwaitingInput`. Exit 0 is **only a local observation**, not global transport drain or
an admission lock. `read` does not write. A `SNAPSHOT` from a write precedes save/commit; inspect
`COMMITTED` or read committed storage before inferring durable success. Signals have no durable
input receipt: inspect progress after an ambiguous commit before retrying.

Current's `WORKFLOW_DEPLOYMENT_MODE=incompatible` selects definition version 2; `missing-binding`
renames the saved continuation and `wire-break` changes its reply schema while retaining version 1.
These deliberately bad releases fail with exit 10. Unset the mode (or use `compatible`) and rerun
`process` to recover a valid retained reply after its inbox retry delay. Do not rewrite the process
version, reply payload or completed ledger to silence the error. Malformed required input is not
repaired by reinstalling compatible code.

Automated process proofs start disposable PostgreSQL 18.6 with Testcontainers:

```bash
dotnet test --project src/Gloaming.Messaging/tests/WorkflowDeploymentTests/WorkflowDeploymentTests.csproj --no-progress --no-ansi --output Normal --show-stdout Failed --show-stderr Failed
```

On the local Podman setup, set `DOCKER_HOST=unix:///run/user/1000/podman/podman.sock` and
`TESTCONTAINERS_RYUK_DISABLED=true`. The tests additionally kill Current after its real database
save and before inbox completion/commit, then recover in another process. The controlled cut uses
`WORKFLOW_DEPLOYMENT_PAUSE_AFTER_SAVE=true`; keep this test setting unset for ordinary commands.
